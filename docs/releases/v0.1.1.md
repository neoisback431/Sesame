<h1 align="center">Sesame 0.1.1 · Installer en quelques minutes</h1>

<p align="center"><em>Un domaine, un fournisseur d'identité : Sesame tourne, sur un serveur Docker ou sur AWS.</em></p>

---

Cette version ne change pas le comportement de Sesame : elle le rend **simple à
déployer**. Chaque Release embarque désormais deux kits prêts à l'emploi, construits sur les
images publiées, sans cloner le dépôt.

> **Légende** · ✨ nouveauté · 🐳 déploiement · ☁️ AWS · 🧰 outillage · 📚 documentation · ⚠️ à savoir

## 🐳 Kit Docker Compose — `sesame-deploy-v0.1.1.tar.gz`

- ✨ Sesame, PostgreSQL et Nginx sur un seul serveur, à partir des images GHCR.
- ✨ Configuration minimale dans `.env` : **un domaine**, l'émetteur et les deux clients de votre fournisseur d'identité, le groupe des administrateurs. Toutes les adresses en découlent (`<domaine>`, `admin.<domaine>`, `<appli>.<domaine>`).
- ✨ `generate-keys.sh` crée les clés de chiffrement et le mot de passe de la base (relançable, ne remplace jamais une valeur existante).
- ✨ Nginx configuré automatiquement à partir du domaine ; il suffit de déposer le certificat dans `certs/`.
- ✨ Variables obligatoires vérifiées au démarrage, avec un message explicite.

## ☁️ Kit AWS — `sesame-aws-v0.1.1.tar.gz`

- ✨ Terraform / OpenTofu, dans votre **VPC existant** : services sur **ECS Fargate**, base sur **RDS PostgreSQL 17**, **ALB** avec certificat **ACM** à la place de Nginx.
- ✨ Certificat et DNS créés automatiquement si vous fournissez une zone Route 53 (sinon, certificat existant).
- ✨ Clés générées par Terraform, gardées dans **Secrets Manager** et injectées dans les tâches ; tâches sans rôle IAM.
- ✨ Base privée, chiffrée, sauvegardée, protégée contre la suppression ; ALB interne par défaut ; journaux et audit dans **CloudWatch** (365 jours).
- ✨ Redéploiement annulé automatiquement si une nouvelle version ne démarre pas.

## 🐳 Images et environnement de dev

- 🐳 Images de l'administration et du recorder **autonomes** : le schéma des descripteurs y est intégré (plus de montage depuis le dépôt).
- 🐳 `docker compose` ne lance plus que Sesame (portail, proxy, admin, recorder) avec PostgreSQL et Nginx ; le Keycloak de dev devient facultatif et le fournisseur d'identité se branche par `.env`.

## 🧰 Outillage

- 🧰 `make release-kit` produit les deux archives, jointes automatiquement à chaque Release.
- 🧰 Workflow de release sur `actions/checkout@v5` (Node.js 24).

## 📚 Documentation

- 📚 README réécrit autour de l'installation : prérequis, cinq étapes, adresses, ajout d'une application en trois étapes.
- 📚 Guide du kit AWS (`deploy/aws/README.md`) et deux nouvelles décisions d'architecture (ADR 0027, 0028).

## ⚠️ À savoir

- ⚠️ **Dev** : `make up-demo` et `make e2e` exigent désormais de décommenter Keycloak dans `docker-compose.yml` (voir `docs/dev.md`).
- ⚠️ **AWS** : l'état Terraform contient les clés de chiffrement ; stockez-le dans un backend chiffré à accès restreint. Ne régénérez jamais `secrets_encryption_key`.
- ⚠️ Le kit AWS préconfigure OIDC ; pour SAML, ajoutez les variables `SESAME_SAML_*` dans `ecs.tf`.

## 🚀 Démarrer

```sh
VERSION=v0.1.1
curl -L https://github.com/neoisback431/Sesame/releases/download/$VERSION/sesame-deploy-$VERSION.tar.gz | tar xz
cd sesame && ./generate-keys.sh   # crée .env et génère les clés
# renseigner .env, déposer le certificat dans certs/, puis :
docker compose up -d
```

Sur AWS : `sesame-aws-v0.1.1.tar.gz`, puis `terraform init && terraform apply` (voir le guide inclus).
