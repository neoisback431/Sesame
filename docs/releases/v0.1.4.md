<h1 align="center">Sesame 0.1.4 · Le recorder comprend les pages sans formulaire</h1>

<p align="center"><em>n8n et les applications du même type s'embarquent désormais.</em></p>

---

Correctif ciblé du **recorder** (bouton « Analyser une page de login » de l'administration).

> **Légende** · 🐛 correction · 🧭 embarquement · ⚠️ à savoir

## 🐛 Correction

- 🐛 **Pages de login sans `<form>`** (n8n, et plus généralement les interfaces construites en JavaScript) : l'analyse ne s'arrête plus sur `password_field_outside_form`.
- 🧭 Quand les champs sont dans des `<div>` avec un bouton `type=button`, le plus petit bloc qui contient le mot de passe, un bouton et l'identifiant est traité comme le formulaire. L'analyse, la soumission factice interceptée et la connexion avec **compte de test** fonctionnent ; le descripteur proposé utilise `use_form: false` avec la requête observée (JSON ou formulaire).

## ⚠️ À savoir

- ⚠️ Pour obtenir un descripteur complet (cookie de session, page d'arrivée), renseignez un **compte de test** dans l'analyse ; sans lui, le recorder liste les points à confirmer.
- ⚠️ Le correctif est dans l'image **`sesame-recorder`** : mettez à jour la version pour en profiter.
- ⚠️ Rappel de la 0.1.3 : les identifiants d'application `new`, `admin` et `www` sont réservés.

## 🚀 Mettre à jour

```sh
# Docker Compose : dans le dossier du kit
sed -i 's/^SESAME_VERSION=.*/SESAME_VERSION=v0.1.4/' .env
docker compose pull && docker compose up -d
```

Sur AWS : `sesame_version = "v0.1.4"` puis `terraform apply`.
