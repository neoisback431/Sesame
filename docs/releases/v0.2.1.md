<h1 align="center">Sesame 0.2.1 · Les flux longs ne sont plus coupés</h1>

<p align="center"><em>Le délai vers l'appli devient un délai d'inactivité : SSE, pings et téléchargements passent tant que l'appli émet.</em></p>

---

Correctif du **proxy**.

> **Légende** · 🐛 correctif · ⚠️ à savoir

## 🐛 Correctif

- ⏱️ **`spec.upstream.timeout` est désormais un délai d'inactivité** : il borne la connexion, l'attente des en-têtes, puis l'intervalle entre deux morceaux du corps. Ce n'était jusqu'ici une durée **totale** par requête relayée : un flux vivant plus long que le délai (SSE avec ping régulier, flux « push », téléchargement) était interrompu en cours de corps.
- 🔐 Le **rejeu du login** reste borné en durée totale par la même valeur.

## ⚠️ À savoir

- ⚠️ Le défaut reste `30s`. Pour un flux qui ne pingue que toutes les N secondes, mettez `spec.upstream.timeout` **au-dessus de N** (par exemple `90s` pour un ping toutes les 60 s).
- ⚠️ Les frontaux ont leur propre délai d'inactivité : Nginx (`proxy_read_timeout`, 60 s par défaut, non réglé dans le kit) et l'ALB AWS (`idle_timeout = 120` dans le kit). Gardez-les au-dessus de l'intervalle de ping.
- ⚠️ Le changement est dans l'image **`sesame-proxy`** et vaut pour toutes les applis.

## 🚀 Mettre à jour

```sh
# Docker Compose : dans le dossier du kit
sed -i 's/^SESAME_VERSION=.*/SESAME_VERSION=v0.2.1/' .env
docker compose pull && docker compose up -d
```

Sur AWS : `sesame_version = "v0.2.1"` puis `terraform apply`.
