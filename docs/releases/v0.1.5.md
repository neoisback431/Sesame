<h1 align="center">Sesame 0.1.5 · Se reconnecter après une déconnexion</h1>

<p align="center"><em>Un utilisateur qui se déconnecte d'une application retrouve l'accès au prochain clic.</em></p>

---

Correctif du **proxy**.

> **Légende** · 🐛 correction · ⚠️ à savoir

## 🐛 Correction

- 🐛 **Déconnexion faite dans l'application** : après un « Se déconnecter » de l'appli elle-même, le clic suivant dans Sesame renvoyait sur la page de login de l'appli, sans moyen de se reconnecter (l'utilisateur ne connaît pas les identifiants).
- 🐛 Cause : l'appli efface son cookie de session ; Sesame retirait le cookie de son jar mais gardait la session et relayait sans cookie. Une session applicative à laquelle il manque un cookie de session est désormais supprimée et le login rejoué, **sans règle à écrire dans le descripteur**. Les sessions déjà enregistrées dans cet état sont aussi corrigées.

## ⚠️ À savoir

- ⚠️ Le correctif est dans l'image **`sesame-proxy`**.
- ⚠️ Une application qui invalide sa session **côté serveur sans effacer son cookie** reste reconnue par `spec.expiry` (statut, redirection, marqueur) ou `spec.logout.paths` : à renseigner pour ces applications.
- ⚠️ Rappels : 0.1.4 (recorder : pages de login sans `<form>`, ex. n8n) et 0.1.3 (noms des utilisateurs, identifiants `new` / `admin` / `www` réservés).

## 🚀 Mettre à jour

```sh
# Docker Compose : dans le dossier du kit
sed -i 's/^SESAME_VERSION=.*/SESAME_VERSION=v0.1.5/' .env
docker compose pull && docker compose up -d
```

Sur AWS : `sesame_version = "v0.1.5"` puis `terraform apply`.
