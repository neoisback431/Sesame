<h1 align="center">Sesame 0.1.7 · L'appli connaît son adresse publique</h1>

<p align="center"><em>Le proxy annonce l'adresse publique par X-Forwarded-* : fini les URLs internes derrière l'ALB.</em></p>

---

Évolution du **proxy**.

> **Légende** · ✨ nouveauté · ⚠️ à savoir

## ✨ Nouveauté

- 🌐 **Adresse publique annoncée à l'appli** : le proxy pose `X-Forwarded-Host`, `X-Forwarded-Proto` et `X-Forwarded-Port` sur chaque requête relayée **et** sur le rejeu du login. Les valeurs viennent du descripteur (`spec.public.host`, schéma du portail), jamais du client.
- 🛡️ Les `X-Forwarded-Host`, `-Proto`, `-Port` et `Forwarded` fournis par le navigateur ou par un frontal sont **remplacés** ; `X-Forwarded-For` (adresse du client) est conservé.
- ☁️ Derrière l'**ALB AWS**, qui ne pose pas `X-Forwarded-Host`, l'appli connaît désormais son adresse publique. La réécriture d'URL reste en filet.

## ⚠️ À savoir

- ⚠️ Le changement est dans l'image **`sesame-proxy`** et vaut pour **toutes** les applis (ADR 0032).
- ⚠️ Chaque appli doit **faire confiance** à ces en-têtes pour en profiter : par exemple `N8N_PROXY_HOPS=1` pour n8n, `USE_X_FORWARDED_HOST` pour Django, `trust proxy` pour Express. Une appli qui les ignore se comporte comme avant.
- ⚠️ Pour annoncer l'adresse publique, **ne mettez pas** `spec.upstream.host_header` à l'hôte public : beaucoup d'applis répondent `400` à un hôte qu'elles ne connaissent pas.

## 🚀 Mettre à jour

```sh
# Docker Compose : dans le dossier du kit
sed -i 's/^SESAME_VERSION=.*/SESAME_VERSION=v0.1.7/' .env
docker compose pull && docker compose up -d
```

Sur AWS : `sesame_version = "v0.1.7"` puis `terraform apply`.
