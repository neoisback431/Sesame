<h1 align="center">Sesame 0.1.2 · Demandes d'accès et notifications</h1>

<p align="center"><em>Un utilisateur sans compte demande l'accès depuis le portail ; les administrateurs sont prévenus par mail.</em></p>

---

Jusqu'ici, une tuile grisée dans « Mes applications » était un cul-de-sac : l'utilisateur
devait aller voir un administrateur. Cette version lui permet de **demander l'accès
lui-même**, et prévient les administrateurs **par mail**, sans jamais mettre un serveur
SMTP dans le chemin d'une connexion.

> **Légende** · ✨ nouveauté · 🔒 sécurité · 🛠️ administration · 📧 notifications · 🐳 déploiement · ☁️ AWS · 📚 documentation · ⚠️ à savoir

## ✨ Demandes d'accès (ADR 0029)

- ✨ Sur une tuile grisée, deux parcours :
  - **« J'ai déjà un compte »** : l'utilisateur saisit ses identifiants applicatifs. Sesame les **vérifie par un rejeu de test** (une seule tentative, pour ne pas verrouiller le compte), les enregistre chiffrés dans le coffre, et crée un compte `pending`. L'administrateur n'a plus qu'à l'activer.
  - **« Je n'ai pas de compte »** : l'administrateur voit la demande et crée le compte.
- ✨ La tuile affiche « demande en cours » tant que la demande n'est pas traitée.
- 🛠️ Nouvelle page **« Demandes d'accès »** dans l'administration : activer, refuser (supprime le secret et le compte en attente) ou créer le compte avec l'utilisateur prérempli. La demande se clôt toute seule quand le compte est activé, supprimé, désactivé ou provisionné.
- 🛠️ Nouvel état de compte `pending`, visible dans les pages de comptes ; compteur sur l'accueil.
- 🔒 Les identifiants saisis ne transitent que du portail vers le proxy, par un **service interne** protégé par jeton (`SESAME_INTERNAL_TOKEN`), jamais exposé par Nginx ni par l'ALB. Ils ne sont ni journalisés, ni renvoyés, ni relisibles depuis l'administration ; un compte existant n'est jamais écrasé ; le rejeu reste refusé tant que le compte est `pending`.

## 📧 Notifications par mail (ADR 0030)

- 📧 Les administrateurs sont prévenus d'une **nouvelle demande d'accès**, d'un **compte passé en échec**, d'une **application injoignable** et des **actions d'administration sensibles** (compte supprimé ou désactivé, etc.).
- 📧 **Boîte d'envoi en base** : le portail et le proxy déposent l'événement, l'administration l'expédie. Un SMTP en panne ne bloque ni connexion, ni rejeu, ni demande. Reprise avec attente croissante, abandon après 6 essais, purge à 30 jours, regroupement des répétitions sur 10 minutes.
- 🛠️ Page **« Notifications »** : serveur, sécurité, expéditeur, destinataires, événements activés, mail de test et historique, le tout réglable dans la console.
- 🔒 Le mot de passe SMTP vit dans `SESAME_SMTP_PASSWORD`, **jamais en base** ; un SMTP sans chiffrement est refusé.

## 🐳 Kits de déploiement

- 🐳 **Kit Docker Compose** : `generate-keys.sh` génère le nouveau jeton `SESAME_INTERNAL_TOKEN` ; `SESAME_SMTP_PASSWORD` est facultatif dans `.env`.
- ☁️ **Kit AWS** : le jeton est généré par Terraform et gardé dans Secrets Manager ; le portail joint le service interne du proxy par Service Connect (`proxy-internal:8082`).

## ⚠️ À savoir

- ⚠️ **Mise à jour** : relancez `generate-keys.sh` (kit Compose) avant `docker compose up -d`. Sans `SESAME_INTERNAL_TOKEN`, seule l'option « Je n'ai pas de compte » est proposée. Sur AWS, `terraform apply` suffit.
- ⚠️ Deux **migrations** automatiques au démarrage (`0006` demandes d'accès, `0007` notifications).
- ⚠️ « J'ai déjà un compte » exige le **coffre PostgreSQL** (le défaut) : avec OpenBao / Vault, le service répond « non pris en charge ».
- ⚠️ **AWS** : le kit ne porte pas encore le mot de passe SMTP. Les notifications fonctionnent avec un relais SMTP sans authentification ; sinon, ajoutez `SESAME_SMTP_PASSWORD` au service `admin` dans `ecs.tf`.
- ⚠️ Version 0.x : la configuration et le format des descripteurs peuvent encore évoluer.

## 🚀 Démarrer

```sh
VERSION=v0.1.2
curl -L https://github.com/neoisback431/Sesame/releases/download/$VERSION/sesame-deploy-$VERSION.tar.gz | tar xz
cd sesame && ./generate-keys.sh   # crée .env et génère les clés
# renseigner .env, déposer le certificat dans certs/, puis :
docker compose up -d
```

Sur AWS : `sesame-aws-v0.1.2.tar.gz`, puis `terraform init && terraform apply` (voir le guide inclus).
