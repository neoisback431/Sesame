<h1 align="center">Sesame 0.1.3 · Des noms, pas des clés</h1>

<p align="center"><em>L'administration affiche « Alice Martin » au lieu d'un identifiant illisible.</em></p>

---

Version de confort et de robustesse : l'administration devient lisible, un identifiant
d'application piégeux n'est plus possible, et la configuration d'Entra ID est mieux expliquée.

> **Légende** · ✨ nouveauté · 🐛 correction · 🛠️ administration · 🗄️ base de données · 📚 documentation · ⚠️ à savoir

## 🛠️ Administration

- ✨ **Noms des utilisateurs** (ADR 0031) : le nom et l'e-mail s'affichent à la place de la clé (l'`oid` d'Entra, du type `CmPymIROfTM_…`), avec la clé en petit dessous. Pages concernées : utilisateurs, comptes d'un utilisateur, comptes d'une application, demandes d'accès, notifications.
- ✨ La **recherche** d'un utilisateur porte sur le nom, l'e-mail et la clé ; les suggestions de création de compte portent le nom.
- 🔒 Aucune autorisation n'en dépend : habilitations, coffre, registre et audit restent sur la clé. Le nom et l'e-mail ne figurent ni dans l'audit, ni dans les mails de notification.

## 🐛 Corrections

- 🐛 **Identifiants d'application réservés** : `new`, `admin` et `www` sont refusés (portail, proxy, administration). Le recorder déduisait l'identifiant du premier label de l'hôte de l'appli, donc `www.exemple.com` donnait `www`.
- 🐛 Le **recorder** ignore désormais les labels génériques (`www`, `login`, `sso`…), propose le suivant (`exemple`), signale l'identifiant déduit comme « à confirmer » et bloque un identifiant réservé.

## 🗄️ Base de données

- 🗄️ Migration `0008` (table `users`), appliquée automatiquement au démarrage du portail.

## 📚 Documentation

- 📚 **Entra ID** : `SESAME_ADMIN_GROUP` est le **GUID** du groupe (son *Object Id*), pas son nom. Les groupes doivent être activés dans les deux applications Entra : *Configuration du jeton* → revendication de groupes, ou `"groupMembershipClaims": "SecurityGroup"` dans le manifeste. Précisé dans le README, la référence de configuration (nouvelle section), les `.env.example` et le kit AWS.

## ⚠️ À savoir

- ⚠️ **Noms** : un utilisateur prend son nom à **sa prochaine connexion** au portail ; d'ici là (ou s'il n'est jamais venu), la clé reste affichée. Entra doit émettre `name` et `email` (jeton d'ID, portées `profile email`).
- ⚠️ **Donnée personnelle** : le nom et l'e-mail sont désormais conservés en base, en plus de la clé. À signaler dans votre analyse de conformité.
- ⚠️ **Identifiants réservés** : une application déjà enregistrée sous `new`, `admin` ou `www` est écartée au chargement ; recréez-la sous un autre identifiant (ses comptes et identifiants sont à ressaisir).
- ⚠️ Version 0.x : la configuration et le format des descripteurs peuvent encore évoluer.

## 🚀 Mettre à jour

```sh
# Docker Compose : dans le dossier du kit
sed -i 's/^SESAME_VERSION=.*/SESAME_VERSION=v0.1.3/' .env
docker compose pull && docker compose up -d
```

Sur AWS : `sesame_version = "v0.1.3"` puis `terraform apply`.
