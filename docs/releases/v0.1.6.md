<h1 align="center">Sesame 0.1.6 · Se reconnecter après une déconnexion (mode handoff)</h1>

<p align="center"><em>Le correctif de la 0.1.5, étendu aux applis en mode handoff (ex. n8n).</em></p>

---

Correctif du **proxy**.

> **Légende** · 🐛 correction · ⚠️ à savoir

## 🐛 Correction

- 🐛 **Déconnexion faite dans l'application, mode `handoff`** : l'appli efface son cookie de session dans le navigateur, mais le marqueur de remise de Sesame restait : Sesame croyait la remise faite, relayait sans rien refaire, et l'utilisateur retombait sur la page de login de l'appli.
- 🐛 Sur une navigation, l'absence d'un cookie remis (`session.handoff.set_cookies`) déclenche maintenant une nouvelle remise, **sans règle à écrire dans le descripteur**.

## ⚠️ À savoir

- ⚠️ Le correctif est dans l'image **`sesame-proxy`**.
- ⚠️ Pour une remise par stockage local seul (sans `set_cookies`), rien n'est détectable côté serveur : `spec.expiry` reste nécessaire.
- ⚠️ La 0.1.5 corrigeait le mode `proxy` uniquement.

## 🚀 Mettre à jour

```sh
# Docker Compose : dans le dossier du kit
sed -i 's/^SESAME_VERSION=.*/SESAME_VERSION=v0.1.6/' .env
docker compose pull && docker compose up -d
```

Sur AWS : `sesame_version = "v0.1.6"` puis `terraform apply`.
